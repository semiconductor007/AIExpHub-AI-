# AI 实验总结使用与验收

2026-10-27：已实现后端快照预览、DeepSeek 客户端、比较页总结展示与自动过期提示。用户配置后，以独立数据库中的合成实验完成真实 DeepSeek 调用验收；不将模拟验收或单次成功当作所有分析内容准确性的保证。

## 配置与启用

本地配置文件是 `backend/.env`，已被 Git 忽略。文件不存在时，从 `backend/.env.example` 复制一份；已有文件不要覆盖。后端新增 `python-dotenv==1.2.4`，并将已有开发依赖 `httpx==0.28.1` 列为运行依赖。首次更新后在项目根目录执行：

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

在本地 `.env` 填写：

```dotenv
AI_SUMMARY_ENABLED=true
DEEPSEEK_API_KEY=在这里填写自己的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

模型 ID 示例参考 2026-10-27 的 [DeepSeek 官方说明](https://api-docs.deepseek.com/)，使用账户实际可用模型。更改配置后重启后端：一键启动用户先运行“停止平台.cmd”，再运行“启动平台.cmd”；手动启动用户 Ctrl+C 后重新执行原 uvicorn 命令。配置在首次使用时读取并缓存，进程环境变量优先于固定路径的 `.env`，不进行变量插值。不要把 Key 写到前端、截图、聊天或 Git。

支持配置总超时 5–120 秒（默认 60）、最大输出 512–8000 tokens（默认 3000）、最多 2–10 个实验（默认 10）、完整消息上限 4096–131072 UTF-8 字节（默认 32768）。启动和健康检查不会连接 DeepSeek；配置缺失 / 错误时原业务仍然可用。第一版仅允许官方 HTTPS 服务根地址，不接受浏览器传入服务地址，不跟随重定向。

## 使用顺序

1. 在比较页加入同一项目的 2–10 个不同实验，可先正常比较和查看图表。
2. 切换到“AI 总结”标签，点击“预览 AI 总结”。至少两个实验有结果，且至少一项指标在两个实验中都有值，否则会提示数据不足。
3. 可选主指标，参数默认不发送。勾选具体参数路径后，点击“更新发送预览”。`/evaluation/dataset` 表示嵌套字段，`/x~1y/0` 表示键 `x/y` 的数组第一个元素；缺失参数与显式 null 分开记录。
4. 核对实验编号、模型、基准、参数数量，并展开完整消息确认数据范围；确认后点击“发送并生成”。只有此步访问模型，可能产生费用。
5. 查看五个章节和确定性事实，按需复制。数据变化后旧总结显示过期提示；重新预览确认后才会重新生成。

跨项目仍可比较和导出，第一版 AI 总结暂限同项目。没有主指标时逐项解释，不提供综合排行榜。空结果、缺失单项、0、最佳并列、自定义方向与单位保留原业务含义。

图表沿用现有 ECharts 和 PNG 导出，模型不产生绘图脚本或数值。旧总结与刷新后的图表可能属于不同快照，过期提示用于明确这一点；复制文本包含时间、模型、对应实验、事实和过期状态。

## 后端协议

新增端点均不写数据库，不新增业务表。

| 端点 | 用途 |
| --- | --- |
| `GET /ai/summaries/status` | 本地配置是否就绪及提示；不返回 Key，不访问服务商 |
| `POST /ai/summaries/preview` | 从数据库生成快照、参数路径候选、主指标候选、事实和完整 messages |
| `POST /ai/summaries/check` | 比较当前数据摘要，用于切回页面、成功刷新比较后和复制前检查；不调用模型 |
| `POST /ai/summaries/generate` | 检查已确认摘要，单次调用模型，验证输出，再检查数据是否变化 |

预览请求：`experiment_ids`（必填）、`baseline_experiment_id`（可为 null）、`primary_metric`（可为 null）、`parameter_paths`（默认空数组）。系统指标标识例如 `system:accuracy`，自定义标识含项目 ID、指标 ID 和 key；使用预览返回的候选，不用显示名称猜测标识。

check 在上述请求上增加 `fingerprint`；generate 再增加唯一 UUID `request_id`。前端不提交指标值。预览后数据或模型配置变化返回 409，要求重新预览。摘要覆盖编号、模型、全部参数、当前指标定义 / 数值、基准、主指标和规则版本；未选参数只参与本地摘要，不发送给模型。

单进程生成并发上限 1；请求 ID 保留 5 分钟防重，最多 256 项。调用失败也保留 ID，防止网络重发造成重复计费；该机制不是跨进程的全局防重。没有 AI 自动重试或自动定时调用。输入 / 选择非法返回 422，资源不存在返回 404，数据变化 / 重复 / 忙碌返回 409，短期请求数限制返回 429，配置不可用返回 503，服务商失败 / 非法内容返回 502，总超时返回 504。

响应采用固定五章节，每条带观察 / 推测 / 建议类别、实验 / 指标 / 证据引用。模型只输出类别、叙述与 evidence_ids；后端校验已知证据，再从证据推导 experiment_ids / metric_ids，避免要求模型重复填写三份关联导致不一致。发送完整 JSON Schema 和五章节结构示例，证据 ID 不存在、字段不符、章节缺失或超长仍被拒绝。数值事实独立由后端展示；结构校验不能证明自然语言推理完全正确，结论仍需核对评测口径与实验条件。当前规则版本为 ai-summary-v3。
