# 后续改进计划

制定日期：2026-10-13。本轮仅形成计划，不实现功能、不修改数据库或依赖。本文是后续阶段的建议范围；用户指定启动某阶段后，再确定具体接口与交互细节。

## 当前基础与目标

现有项目已支持项目 / 批次 / 实验 / 结果管理、项目共享指标、比较表格和图表，以及 JSON 自动填入、文件录入、项目模板与批量导入。最近一次验证为后端 169 个测试、文件读取 4 个测试、前端构建通过，记录见 [文件导入说明](json-file-import.md)。

下一轮主要解决两个问题：比较时明确相对基准的收益与代价；创建参数对照实验时减少重复配置。随后完善评测口径和真实脚本输出。保留课程阶段 6B 的人工窗口拖动、本人讲解与视频交付待办，不将功能增量视为课程验收完成。

| 阶段 | 优先级与目标 | 预计产物 | 验收方式 |

| I3：评测条件填写规范 | 随后。提高比较结论的可信度，先以文档规范落地。 | 项目说明 / parameters 的填写约定、真实示例、比较前核对清单。 | 同一组实验能解释测试集、版本、评测方法和指标口径；缺失信息不被假定为一致。 |

## I1：基准实验与差值比较

### 范围与建议规则

- 从已选实验中选择一个基准；不选择基准时保留当前比较行为。
- 第一版展示绝对差值：当前实验数值减去基准数值，保留原单位与原始数值。例如 accuracy 从 0.80 到 0.83，差值为 +0.03；耗时从 30 ms 到 18 ms，差值为 -12 ms。
- max 指标差值为正表示改善，min 指标差值为负表示改善；反向为退步，真实差值为 0 为无变化。改善标记与现有最佳 / 并列最佳是不同含义，分别展示。
- 基准或当前实验没有结果 / 单项指标缺失时，显示无法比较及原因，不补 0；有效值 0 正常参与计算。基准自身有值的指标差值为 0。
- 自定义指标仍限所属项目。基准不属于该指标项目时不计算差值，不合并跨项目同名指标。系统五项保留既有跨项目数值比较规则，但不据此断言评测条件相同。
- 移除基准或改变选中实验后清空旧比较状态；重新比较使用最新结果，避免展示旧差值。
- 格式化应消除常见浮点显示尾差，但不能把真实非零变化标为“无变化”；极大数相减溢出时不得返回 NaN / Infinity，应明确无法计算。

建议由后端在现有只读比较流程中统一计算，前端使用同一次响应展示，保持无结果逐条查询、无比较历史、无新增业务表。具体请求 / 响应字段在启动 I1 时确定，保留不选择基准时的接口兼容性。

### 验收重点

- accuracy 0.80 → 0.83 显示改善 +0.03；loss 0.4 → 0.3 显示改善 -0.1，反向正确标为退步。
- 覆盖基准为 0、单项为空、无 Result、相同值、正负自定义指标及大数边界。
- 原最佳与并列最佳不受基准选择影响；跨项目自定义指标不能借用基准数值。
- 结果更新后重新比较，原始值、差值、状态同步变化；一次比较请求获取所需信息，保持只读。

第一版不做相对百分比变化、综合评分、加权排行榜、显著性检验或额外差值图表。绝对差值先满足日常判断，避免基准为 0 的百分比问题和不同单位混合排名。

## I2：复制实验配置

### 范围与建议规则

- 当前批次实验列表增加“复制配置”，打开已有创建表单，复制模型名称、parameters 和可编辑备注。
- 实验编号留空，由用户填写新编号；沿用 trim + uppercase 和系统全局唯一规则，不引入自动编号。
- 参数使用独立副本，修改嵌套参数也不能改变源实验。
- 第一版保存到当前批次，创建新的 Experiment；不复制结果、ID 或创建时间，不关联历史版本、不移动源实验。
- 用户核对后才创建，取消不写数据库；保存后可以继续用文件或手动方式录入新结果。

### 验收重点

- 模型、参数和备注正确填入，空编号和重复编号被拒绝。
- 修改嵌套参数后，源实验参数和结果不变。
- 新实验使用服务端创建时间，Result 为空；取消、校验失败和网络失败不产生半成品。
- 原手动新建、编辑、删除、批量导入与选择上下文正常。

优先复用已有 Experiment 创建接口与表单，不为复制单独新增数据库字段或业务关系。

## I3：评测条件填写规范

先提供可选填写约定：项目说明记录评测任务、数据集 / 测试集版本与指标计算口径；parameters 可包含 evaluation 对象，记录该实验的具体条件，例如：

```json
{
  "seed": 42,
  "evaluation": {
    "dataset": "请填写实际数据集",
    "dataset_version": "请填写实际版本",
    "split": "test",
    "method": "请填写实际评测方式"
  }
}
```

这些是建议键，不是强制参数，已有实验和不同模型自由参数保持有效。先用真实实验确认约定是否够用；如果后续需要自动判断可比性，再另行确定专门字段与校验规则。

本阶段依靠说明与人工核对，不自动将未填写条件的实验判断为一致，不伪造数据集版本，不增加数据集管理模块。

## I4：评测脚本输出对接

启动前需要现用评测脚本或有代表性的输出样例，以及指标含义、单位和对应项目。届时检查数据格式与模型任务，不预先假定所有脚本都输出 accuracy / f1。

第一版只适配一个实际使用的脚本：读取真实实验配置和已经计算好的指标，按 [现有导入格式](json-file-import.md#文件格式) 写出 JSON。保留 0 / null、参数、编号和指标单位；导出的自定义指标须先属于项目定义，不静默转换单位或扩大范围。

验收使用真实输出与导入后的详情逐项核对，并检验未知指标、非法数值和重复编号能被预览识别。不编造指标，不代跑未知训练任务，不增加平台调度、后台任务或外部 AI 服务；直接自动写入 API 另行讨论，第一版继续通过预览确认导入。

## 每阶段的共同完成条件

1. 完成该阶段授权范围，更新必要使用说明，不顺带扩充其他业务。
2. 运行对应新增测试及原有回归，完成前端类型检查和构建；测试数量以实际执行结果记录。
3. 用独立临时数据做真实页面验证；清理本轮创建的数据，核对原有数据保留，原课程 Word 不修改。
4. 检查独立提交范围，排除数据库、备份、依赖目录、构建产物及临时截图；按既有仓库协作方式提交、推送 main。
5. 汇报变更、验证、限制与 Git 状态；完成当前阶段后停止，等待用户下一步指令。

第一项建议启动 I1：基准实验与绝对差值表格。I2 完成后进行交付范围收敛，不以计划文档替代实际实现或验收。
