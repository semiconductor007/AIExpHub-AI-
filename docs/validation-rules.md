# 业务校验规则

当前阶段：阶段 2.5，冻结数据库实现前的剩余业务决策。以下是未来实现必须遵守的业务规则，不包含校验代码、数据库约束、路由、请求格式或完整 HTTP API。

## 字段必填规则

| 对象 / 属性 | 已确定规则 |
| --- | --- |
| Project.`name` | 必填；缺失、空值、空字符串和仅含空白字符均不合法。 |
| ExperimentBatch.`name` | 必填；缺失、null、空字符串和仅含空白字符均不合法。 |
| ExperimentBatch.`project_id` | 必须提供有效的所属项目关联。 |
| Experiment.`batch_id` | 必须提供有效的所属批次关联。 |
| Experiment.`model_name` | 必填；缺失、空值、空字符串和仅含空白字符均不合法。 |
| Experiment.`experiment_no` | 必填；缺失、空值、空字符串和仅含空白字符均不合法。 |
| Experiment.`parameters` | 必填，必须为非空 JSON object；字段缺失、null、非对象或 `{}` 均不合法。 |
| ExperimentResult.`experiment_id` | 必须提供有效的所属实验关联。 |

备注及说明仍可选，ExperimentBatch.description 可选。

parameters 必须提供且为非空 JSON object，不允许用数组、字符串、数字、布尔值或 null 替代。参数键不固定，不要求所有模型拥有相同参数，也不要求 learning_rate、batch_size 等具体键存在。例如 `{ "learning_rate": 0.0001, "batch_size": 32, "seed": 42 }` 和 `{ "temperature": 0.7 }` 均合法。

第一版“缺失参数”的明确含义为：parameters 字段未提供、不是 JSON object 或为空对象 `{}`，这些情况均应拒绝。无效 JSON 也应明确报错，不能静默忽略或补默认值；本阶段不追加具体参数键或参数值的校验规则。

## 唯一性规则

- `experiment_no` 由用户输入，不实现自动编号。保存和比较唯一性之前统一执行 trim + uppercase，即先去除首尾空白，再转换为大写；新建和修改遵守同一规范。
- `" exp-001 "`、`"EXP-001"`、`"exp-001"` 均规范化为 `EXP-001`，三者视为同一编号。
- 不强制使用 `EXP-001` 等固定格式，只要求规范化后非空。
- `experiment_no` 在整个系统中全局唯一，不按 Project 或 ExperimentBatch 分区。
- 已存在 `EXP-001` 时，其他项目或批次也不能再次创建同一编号。
- 修改实验编号时也必须检查与其他实验是否冲突；保留该实验自身原编号不算重复。
- 选择全局唯一是为了实现简单、避免实验比较时产生编号歧义，并便于自动化测试与课程验收。
- 一个 Experiment 可以暂时没有 ExperimentResult；一旦录入，最多一份当前有效结果。首次录入创建结果，后续修改更新现有结果，不创建重复结果或历史版本。

本阶段只记录规则，不实现规范化、唯一约束或查询代码。

## 指标范围与数值合法性

| 指标 | 可为空 | 提供时的合法范围 | 比较方向 |
| --- | --- | --- | --- |
| `accuracy` | 是 | 0 ≤ value ≤ 1 | 越大越好 |
| `precision` | 是 | 0 ≤ value ≤ 1 | 越大越好 |
| `recall` | 是 | 0 ≤ value ≤ 1 | 越大越好 |
| `f1` | 是 | 0 ≤ value ≤ 1 | 越大越好 |
| `loss` | 是 | value ≥ 0 | 越小越好 |

提供的指标必须是有限数值。布尔值、非数值文本、空字符串、NaN 和正负无穷不能作为合法指标；第一版不默认将字符串或百分比文本转换成数值。指标为空以无值表示，在 JSON 示例中使用 `null`。

范围包含端点：`accuracy = 0`、`f1 = 1`、`loss = 0` 均合法。`loss` 没有已确定的有限上界，不套用 [0, 1] 规则。展示精度与舍入方式留待后续确定。

## 空结果与修改规则

- 允许部分指标为空，但五项指标不能全部为空。
- 至少一项指标非空，且所有非空指标都必须合法；不能因为一项合法而忽略其他非法指标。
- `0` 是有效结果。例如只有 `loss = 0`、其他指标为空，也满足非空结果规则。
- 修改结果后，完整当前结果仍须通过以上校验，不能把最后一项非空指标清空后留下全空结果。
- 校验失败的修改不得覆盖原有有效结果。
- 修改成功后，后续详情、比较、统计和图表必须使用最新结果，不能保留旧数据作为当前结果。

第一版关系为 Experiment 1 : 0..1 ExperimentResult。允许先创建实验、之后首次录入结果；没有结果不等于“已保存但指标全空的结果”，后者仍明确禁止。修改时省略指标和显式清空指标的请求含义留待后续 API 设计，修改后的完整结果必须遵守上述校验。

## 资源关联规则

- ExperimentBatch 必须属于一个存在的 Project。
- Experiment 必须属于一个存在的 ExperimentBatch。
- ExperimentResult 必须属于一个存在的 Experiment。
- 不允许将新建或修改后的关联指向不存在的父资源。
- 实验所属项目通过批次确定，避免重复关联导致不一致。

## 删除规则

- Project 下仍存在 ExperimentBatch 时拒绝删除；只有没有任何 Batch 的 Project 才允许删除，不级联删除批次。
- ExperimentBatch 下仍存在 Experiment 时拒绝删除；只有没有任何 Experiment 的 Batch 才允许删除，不级联删除实验。
- Experiment 允许删除；如果存在 ExperimentResult，删除 Experiment 时同时删除其 Result，不能留下独立或悬空结果。
- 上述规则只作为业务约定记录，本阶段不实现数据库级联或 API。

## 多实验比较规则

- 允许跨 Project、跨 ExperimentBatch 比较实验。
- 至少选择 2 个不同且真实存在的 Experiment；重复选择同一个实验不能满足最小数量要求。任一所选实验不存在时，应明确报出资源不存在，不能静默忽略。
- 没有 Result 的实验允许被选择并须明确识别为“未录入结果”，不能为其伪造结果。
- 缺失单项指标保持 null，不使用 0 或其他默认值填充；合法指标值 0 正常参与比较。
- accuracy、precision、recall、f1 越大越好，loss 越小越好。
- 分别计算每项指标的最佳实验，只使用该指标非 null 的实验；没有 Result 的实验不参与任何指标的最佳结果计算。
- 若所有所选实验的某项指标都为空，该指标没有最佳实验；全部实验均无 Result 时，各项指标均没有最佳实验。
- 并列最优时，允许多个实验同时标记为该指标的最佳结果，不强行只选一个。
- 比较必须使用各实验最新的当前结果，不使用旧结果或缺失值填充结果。

## 后续 API 预期异常语义

| 情况 | 预期业务语义 |
| --- | --- |
| 必填字段缺失或为空 | 明确表示字段校验失败，并指出对应字段。 |
| parameters 未提供、非 JSON object、为空对象或 JSON 非法 | 明确表示参数校验失败，并说明具体原因，不要求固定参数键。 |
| 实验编号与其他实验重复 | 明确表示实验编号冲突，拒绝本次无效写入。 |
| 指标类型非法、非有限数值或超出范围 | 明确表示指标校验失败，并指出指标及合法范围。 |
| 结果指标全部为空 | 明确表示实验结果不能为空，要求至少一项合法指标。 |
| 所属项目、批次或实验不存在 | 明确表示关联资源不存在，拒绝无效关联。 |
| 查询或修改不存在的资源 | 明确返回“资源不存在”，不能静默成功或假装返回有效详情。 |
| 尝试重复创建同一实验的当前结果 | 明确表示当前结果已存在；后续应修改已有结果。 |
| 删除仍有批次的项目，或删除仍有实验的批次 | 明确表示存在子资源，拒绝删除。 |
| 比较选择不足两个不同实验 | 明确表示比较数量不足，要求至少两个不同实验。 |

具体 HTTP 状态码、错误响应结构和接口路径留待后续阶段设计；本文件只确定业务语义。

## 后续验收示例

| 场景 | 预期结论 |
| --- | --- |
| Project 名称只包含空白字符 | 拒绝，名称不能为空。 |
| Batch 名称缺失、为 null、空字符串或只包含空白字符 | 拒绝，批次名称必填。 |
| parameters 缺失、为 null、数组、字符串、数字或 `{}` | 拒绝，必须提供非空 JSON object。 |
| parameters 为 `{ "temperature": 0.7 }` | 接受，不要求固定参数键。 |
| 在不同项目中再次使用已存在的 `EXP-001` | 拒绝，违反全局唯一规则。 |
| 已有 `EXP-001`，再次输入 `" exp-001 "` | 拒绝，规范化后为同一编号。 |
| 新建实验时尚未录入 Result | 允许；首次录入后最多保留一份当前结果。 |
| `accuracy = 0` 或 `accuracy = 1`，其余为空 | 接受，边界合法且结果非空。 |
| `precision = -0.01` 或 `recall = 1.01` | 拒绝，超出 [0, 1]。 |
| 只有 `loss = 2.5`，其余为空 | 接受，loss 不要求小于等于 1。 |
| 只有 `loss = 0`，其余为空 | 接受，0 不等于空值。 |
| `loss = -0.01`，或任一指标使用布尔值 / NaN | 拒绝，指标非法。 |
| 五项指标全部为空 | 拒绝，空结果不允许保存。 |
| 新实验关联不存在的批次 | 拒绝，关联资源不存在。 |
| 删除有 Batch 的 Project，或删除有 Experiment 的 Batch | 拒绝，不删除已有子资源。 |
| 删除没有 Batch 的 Project，或没有 Experiment 的 Batch | 允许删除。 |
| 删除已有 Result 的 Experiment | 允许，同时删除其 Result。 |
| 选择跨项目、跨批次的两个不同实验比较 | 允许，所有所选实验必须存在。 |
| 比较中部分实验没有 Result 或某项指标为 null | 明确标识并保留缺失状态，不填充默认值；相应缺失值不参与该项最佳计算。 |
| 所有待比较实验的某项指标都为空 | 该指标没有最佳实验。 |
| 某项指标出现并列最优 | 允许标记多个最佳实验。 |
| 已有结果修改成功后重新查看和比较 | 必须使用最新结果。 |

以上是人工审阅和未来测试的依据，本阶段不编写自动化业务测试或实现代码。
