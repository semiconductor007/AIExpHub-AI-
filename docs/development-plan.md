# 阶段开发计划

阶段 1、阶段 2、阶段 2.5、阶段 3A、阶段 3B、阶段 3C、阶段 3D、阶段 3E 已完成，当前仅执行阶段 3F。完成后停止，不自动进入阶段 4。后续阶段为初步计划，进入相应阶段时再逐步确认细节。

| 阶段 | 阶段目标 | 预计产物 | 验收方式 |
| --- | --- | --- | --- |
| 1：项目初始化与需求边界 | 建立干净的项目基础，整理已确认需求与待确认规则。 | 基础目录、README、Git 忽略规则、需求边界与阶段计划。 | 检查文件和目录完整性、原有文件未被覆盖、文档准确反映现状且未提前实现业务功能。 |
| 2：领域模型与业务规则定稿 | 确定四个核心实体的关系、暂定属性、唯一性与校验规则，仅交付设计文档。 | 领域模型、业务校验规则，以及现有需求文档的必要同步。 | 人工核对实体关系、全局唯一性、指标范围、空结果及资源关联规则；确认没有新增工程或业务代码。 |
| 2.5：冻结数据库实现前的剩余业务决策 | 冻结结果可选关系、批次名称、参数、编号规范化、删除及多实验比较规则。 | 已同步的设计文档、独立 Git 提交并推送 main。 | 人工核对 Mermaid 和文字一致、所有指定决策已同步、旧待确认表述已清理；确认仅改设计文档，没有数据库、依赖、API、前端工程或 pytest。 |
| 3A：后端最小可运行工程 + SQLite 数据库连接 | 建立 Python 3.12、FastAPI、SQLAlchemy 2.x 与 SQLite 的最小后端，只提供健康检查。 | 后端基础文件、最少依赖、数据库连接设施与启动说明；不创建业务 ORM 或表。 | 实际启动应用，验证 /health 返回 200、SQLite 文件创建且 SELECT 1 成功、/docs 可访问及正常停止；确认数据库文件不提交。 |
| 3B：SQLAlchemy 业务模型与数据库约束 | 建立四个 SQLAlchemy 2.x 模型，在 SQLite 落实外键、唯一性、指标及非空结果约束，仅完成数据库层。 | 单个 models.py、Base、外键连接事件、启动建表机制与必要文档同步。 | 重新启动应用实际创建四张表；逐项验证外键、RESTRICT、UNIQUE、CHECK、合法边界和 CASCADE，确认临时数据已清理且运行时文件未提交。 |
| 3C：Project + ExperimentBatch 基础 API | 建立请求级 Session、Pydantic Schema，以及项目和批次 CRUD；保持 404 / 409 / 422 与 RESTRICT 规则。 | schemas.py、两个 Router、get_db、当前 API 文档与必要文档同步。 | 真实启动 Uvicorn，通过 HTTP 验证 A–Q、最新数据、名称校验、列表顺序与删除限制；清理临时数据，确认未实现实验、结果或比较 API。 |
| 3D：Experiment 基础 API | 实现实验 CRUD、编号规范化与全局唯一检查、非空 JSON object 校验；保留既有关系和约束。 | 三个 Experiment Schema、experiments.py Router、当前 API 文档与必要阶段同步。 | 真实启动 Uvicorn，通过 HTTP 验证 A–X、编号跨批次唯一、更新排除自身、参数校验、Batch RESTRICT；确认数据库 UNIQUE 有效、数据清空、服务停止，无 Result API。 |
| 3E：ExperimentResult API | 实现结果首次录入、查询和完整更新；校验有限数值、范围及至少一项非空，保留单份结果与删除级联。 | 三个 Result Schema、results.py Router、必要的 422 序列化处理、当前 API 文档与阶段同步。 | 真实启动 Uvicorn，通过 HTTP 验证 A–AA、PUT 清空省略项、更新时间、非有限值拒绝和删除 CASCADE；确认 UNIQUE / CHECK 有效、四表清空、服务停止。 |
| 3F：后端 pytest 自动化验收 | 将 Project / Batch / Experiment / Result 核心规则固化成独立自动化测试，不增加业务功能。 | 开发依赖、pytest.ini、独立临时 SQLite fixture、六个测试文件和简洁测试说明；核心业务规则已通过 pytest 自动验证。 | 在 backend 执行 python -m pytest -q 全部通过；至少三个文件独立通过，打乱顺序仍通过；确认生产数据库未被访问或改动，测试运行文件不提交。 |
| 4：多实验比较与数据一致性 | 支持实验结果比较，保证修改后比较和统计使用最新数据。 | 比较功能与相关一致性验证。 | 使用多组实验核对比较结果，修改数据后再次核对，并验证缺失或非法数据的处理。 |
| 5：结果可视化 | 根据已确认的指标规则展示比较、趋势或最优结果。 | 可视化页面与必要交互。 | 将图表与原始记录、比较结果进行人工核对，检查修改后更新和空数据展示。 |
| 6：测试与课程验收 | 完成核心流程、业务规则及异常场景验证，整理课程交付材料。 | pytest 测试、验证记录、使用说明与演示材料。 | 运行测试，按课程验收标准演示核心流程并检查交付材料。 |
