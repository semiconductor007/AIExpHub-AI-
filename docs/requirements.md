# 需求边界

## 项目定位与当前阶段

项目名称：AI 模型实验结果管理平台（AIExpHub）。选题来源为上级目录《综合实践项目选题与验收标准.docx》的第 14 题。

项目目标是开发用于管理 AI / 机器学习实验结果的 Web 平台，逐步支持实验配置记录、结果保存、多实验比较和可视化分析。

阶段 1、阶段 2 已完成，当前只执行阶段 2.5：冻结数据库实现前的剩余业务决策。本文件记录已确认的业务方向和后续实现细节，不代表这些功能已经实现。领域设计与规则分别见 [领域模型](domain-model.md)和[业务校验规则](validation-rules.md)。

## 已确认的核心业务方向

| 业务方向 | 需求边界 |
| --- | --- |
| 实验项目管理 | 管理实验所属项目，作为组织实验的基础。 |
| 实验批次 / 实验记录管理 | 已确定 Project 1:N ExperimentBatch 1:N Experiment；Experiment 与 ExperimentResult 为 1 : 0..1。 |
| 模型及实验参数记录 | 保存实验所使用的模型与实验参数，便于回顾配置与比较结果。 |
| 实验结果指标记录 | 保存实验产生的评价指标，支持后续查询与比较。 |
| 实验列表与详情 | 查看实验记录及其配置、结果信息。 |
| 多实验结果比较 | 允许跨项目、跨批次比较至少两个不同且真实存在的实验，保留缺失结果和缺失指标的状态。 |
| 后续结果可视化 | 展示实验指标比较、趋势或最优结果；指标方向及并列最优规则已确定，具体图表后续确定。 |

## 后续必须考虑的业务规则

- `experiment_no` 由用户输入，不实现自动编号；保存和比较唯一性前统一 trim + uppercase，规范化后非空且全局唯一，不要求固定编号格式。
- ExperimentBatch.name 必填，缺失、null、空字符串或仅含空白字符均应拒绝；description 仍可选。
- parameters 必填，必须为非空 JSON object；未提供、非对象或 `{}` 均应拒绝。参数键不固定，不要求各模型使用相同参数或必须提供 learning_rate、batch_size 等具体键。
- 第一版指标为 accuracy、precision、recall、f1、loss。前四项范围为 [0, 1]，loss 必须大于等于 0；非空指标必须为合法有限数值。
- 实验可以先创建、暂时没有结果；首次录入创建结果，后续修改更新现有结果，最多一份当前有效结果且不创建历史版本。修改后，后续详情、比较、统计和图表必须使用最新数据。
- 指标允许部分为空，但已录入结果不能全部为空；非法指标、重复编号及全空结果应拒绝。无结果实验必须明确识别，不能伪造结果。
- Project 名称、model_name 与 experiment_no 不能为空；批次、实验和结果必须关联存在的父资源；查询不存在的资源必须明确返回“资源不存在”。
- Project 有 Batch 时拒绝删除，Batch 有 Experiment 时拒绝删除；无相应子资源时允许删除。Experiment 允许删除，并同时删除其已有 Result。
- 比较时至少选择两个不同且真实存在的实验，允许跨项目、跨批次；缺失单项指标保持 null，不使用 0 或其他默认值填充。
- accuracy、precision、recall、f1 越大越好，loss 越小越好；最佳结果仅使用该指标非 null 的实验。某指标全空时没有最佳实验，并列最优时允许多个实验同时标记为最佳。
