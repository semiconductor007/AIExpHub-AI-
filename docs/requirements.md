# 需求边界

## 项目定位与当前阶段

项目名称：AI 模型实验结果管理平台（AIExpHub）。选题来源为上级目录《综合实践项目选题与验收标准.docx》的第 14 题。

项目目标是开发用于管理 AI / 机器学习实验结果的 Web 平台，逐步支持实验配置记录、结果保存、多实验比较和可视化分析。

当前只执行阶段 1：项目初始化与需求边界。本文件记录已确认的业务方向和后续需要明确的规则，不代表这些功能已经实现。

## 已确认的核心业务方向

| 业务方向 | 需求边界 |
| --- | --- |
| 实验项目管理 | 管理实验所属项目，作为组织实验的基础。 |
| 实验批次 / 实验记录管理 | 管理实验批次与具体实验记录；两者关系后续确认。 |
| 模型及实验参数记录 | 保存实验所使用的模型与实验参数，便于回顾配置与比较结果。 |
| 实验结果指标记录 | 保存实验产生的评价指标，支持后续查询与比较。 |
| 实验列表与详情 | 查看实验记录及其配置、结果信息。 |
| 多实验结果比较 | 比较多个实验的结果，比较范围与规则后续确认。 |
| 后续结果可视化 | 展示实验指标比较、趋势或最优结果；具体图表及判定规则后续确认。 |

## 后续必须考虑的业务规则

- 实验编号不能不受控制地重复。编号的生成方式及唯一性范围（全局、项目内或批次内）尚待确认。
- 数值型评价指标必须进行合法性校验。具体指标的取值范围、精度及特殊数值的处理规则尚待确认，不统一假定所有指标都在 0～1 之间。
- 修改实验结果后，后续比较、统计和图表必须使用最新数据，不能继续呈现旧结果。
- 对缺失参数、非法指标、重复实验编号、空结果等异常情况给出明确处理；具体拒绝、提示或允许暂存的规则后续确认。

## 后续需要逐步确认的问题

- 实验项目、实验批次与实验记录的关系，以及编号的唯一性范围。
- 模型与参数的最小记录内容、哪些参数必填，以及缺失参数的处理方式。
- 首批支持的评价指标、合法值范围及“越大越好 / 越小越好”的含义。
- 多实验比较的可比条件，以及缺失指标和空结果是否参与比较、统计。

这些问题先作为讨论事项保留，本阶段不确定完整字段、接口或数据库结构。

## 本阶段交付范围

- 检查现有文件并保留有效内容。
- 建立 `backend/`、`frontend/`、`docs/` 基础目录。
- 整理需求边界、简洁阶段计划和如实描述当前状态的 README。
- 建立适用于暂定技术栈的 Git 忽略规则；前后端暂以占位文件保留目录。

## 本阶段不实施的内容

- 实验项目、批次或记录的 CRUD，以及实验列表、详情、比较和图表功能。
- 完整数据库设计、数据库建表、具体业务 API 和校验逻辑。
- 登录注册、AI API 接入及复杂前端页面。
- 选题文档中的可选 AI 扩展（自动比较实验、分析参数影响、生成实验报告）；这些尚未纳入已确认需求。

前后端框架工程和依赖安装留待后续阶段。本阶段仅完成基础结构与需求整理，不宣称应用可启动或业务可用。
