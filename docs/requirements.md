# 需求边界

## 项目定位与当前阶段

项目名称：AI 模型实验结果管理平台（AIExpHub）。选题来源为上级目录《综合实践项目选题与验收标准.docx》的第 14 题。

项目目标是开发用于管理 AI / 机器学习实验结果的 Web 平台，逐步支持实验配置记录、结果保存、多实验比较和可视化分析。

阶段 1 已完成，当前只执行阶段 2：领域模型与业务规则定稿。本文件记录已确认的业务方向和后续需要明确的规则，不代表这些功能已经实现。领域设计与规则分别见 [领域模型](domain-model.md)和[业务校验规则](validation-rules.md)。

## 已确认的核心业务方向

| 业务方向 | 需求边界 |
| --- | --- |
| 实验项目管理 | 管理实验所属项目，作为组织实验的基础。 |
| 实验批次 / 实验记录管理 | 已确定 Project 1:N ExperimentBatch 1:N Experiment；Experiment 与 ExperimentResult 为 1:1。 |
| 模型及实验参数记录 | 保存实验所使用的模型与实验参数，便于回顾配置与比较结果。 |
| 实验结果指标记录 | 保存实验产生的评价指标，支持后续查询与比较。 |
| 实验列表与详情 | 查看实验记录及其配置、结果信息。 |
| 多实验结果比较 | 比较多个实验的结果，比较范围与规则后续确认。 |
| 后续结果可视化 | 展示实验指标比较、趋势或最优结果；具体图表及判定规则后续确认。 |

## 后续必须考虑的业务规则

- `experiment_no` 在整个系统中全局唯一，不同项目或批次也不能使用重复编号；编号生成与规范化策略尚待确认。
- 第一版指标为 accuracy、precision、recall、f1、loss。前四项范围为 [0, 1]，loss 必须大于等于 0；非空指标必须为合法有限数值。
- 每个实验只有一份当前有效结果，修改时更新该结果。修改后，后续详情、比较、统计和图表必须使用最新数据，不能继续呈现旧结果。
- 指标允许部分为空，但结果不能全部为空；非法指标、重复编号及全空结果应拒绝。缺失参数的具体判定待参数必填规则确认。
- Project 名称、model_name 与 experiment_no 不能为空；批次、实验和结果必须关联存在的父资源；查询不存在的资源必须明确返回“资源不存在”。

## 后续需要逐步确认的问题

- 编号生成方式、大小写和首尾空白的规范化策略，以及删除后编号是否可复用。
- 模型与参数的最小记录内容、哪些参数必填，以及缺失参数的处理方式。
- 指标精度、展示舍入方式及“越大越好 / 越小越好”的比较规则。
- 多实验比较的可比条件，以及部分指标缺失时的比较、统计规则。
- 是否允许先保存无结果实验、首次录入与修改结果的流程，以及父资源删除时的关联处理规则。

这些问题先作为讨论事项保留。本阶段确定核心实体关系与暂定属性，不设计完整接口或数据库表结构。
