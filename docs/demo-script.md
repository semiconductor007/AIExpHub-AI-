# 最终演示脚本草案

用途：阶段 6B 录屏 / 课堂演示；目标时长 **7 分 30 秒**，控制在 5–8 分钟内。当前只有草案，6A 未执行本脚本、创建下面样例或录制视频。课程原文录制时间不限、建议开启前置摄像头；本项目选择短演示以突出得分点。

## 演示前准备

在最终设备按 README 启动 FastAPI 和 Vite，确认 health 正常、四表初始为空，准备好页面与终端，打开项目页、实验页、比较页三个标签。确认所需编号未使用；若已有真实用户数据，不擅自清空或覆盖。终端预先定位 backend，确保 pytest 可用；事先核对复制内容但不要把旧截图 / 输出冒充本次运行。

准备原评分表、acceptance-matrix、设计文档、AI 辅助说明及一个真实 Git diff 供快速说明。本脚本只使用已有页面和 API，不需统计页、登录或外部 AI 服务。

## 7 分 30 秒顺序

| 时间 | 操作与讲解 | 预期证据 |
| --- | --- | --- |
| 0:00–0:30（30s） | 介绍课程第 14 题，说明管理配置 / 结果 / 比较 / 图表，以及 AI 辅助开发与业务 AI 的区别 | 项目定位准确，可选 AI 没有被伪装成已实现 |
| 0:30–0:55（25s） | 首页展示 Hero、三入口、健康正常；点击进入项目管理 | 实际入口与 API 连接，不是统计假数据 |
| 0:55–1:35（40s） | 创建项目 A、批次 A；通过批次“管理实验”进入实验页 | Project → Batch 关联和页面跳转 |
| 1:35–2:20（45s） | 复制 A 的编号、模型、JSON；保存实验，首次录入五指标；刷新页面后重新选中查看 | 编号规范化、参数保存、Result 与持久化闭环 |
| 2:20–3:10（50s） | 创建项目 B / 批次 B / EXP-002 与结果；操作熟练时加入可选 EXP-003 | 两项目真实数据；可选缺失 / 部分结果 |
| 3:10–3:55（45s） | 新建实验尝试重复 `exp-001`，再试参数 `[]` 或 `{}`；取消表单；编辑结果尝试 accuracy=1.2，再恢复原合法值后取消 | 重复编号中文冲突，非法参数 / 范围拦截，失败不破坏数据；不要展示成功的错误写入 |
| 3:55–4:50（55s） | Compare 从 A、B 加入两实验；开始比较；展示摘要、精确表格、综合图和 Loss 图 | 跨项目保留选择、四项 max / Loss min，表与图一致；Network / 访问日志仅一个 Compare POST |
| 4:50–5:35（45s） | 另一实验标签把 A accuracy 改为 0.94，其他四指标保留；回原比较标签点重新比较 | Accuracy 最佳从 B 换为 A，表格 / 图同步更新；其他最佳仍为 B；PUT 为完整更新 |
| 5:35–6:15（40s） | 实际拖动窗口宽 → 中 → 窄 → 恢复，检查图表与 canvas；顺带看控制台 | 补测 5A AA；画布跟随、无叠加和错误，绝不以 iframe 代替 |
| 6:15–6:55（40s） | 删除仍有批次的项目 A、仍有实验的批次 A，显示限制；再删 EXP-001，核对原实验结果 GET 为 404；删除空批次 / 项目 | RESTRICT 与 CASCADE。删除实验后结果 API 的 404 表示实验不存在，物理结果删除由已有 pytest / 数据层证据支撑 |
| 6:55–7:30（35s） | 终端实际运行 pytest，展示 102 passed；快速指向 README 启动说明、设计 / AI 文档和真实提交，说明已知限制 | 可复现测试、交付文档、AI 修改与验证过程；不宣称最终分数 |

时间合计 450 秒。6A 本机 pytest 为 7.15 秒，仍需演示前实测最终设备时长，避免靠隐藏失败或跳过数据输入赶时间。重复编号、参数非法、范围非法都直接展示，不要求现场手输长 JSON。若加演 EXP-003，应缩短已有数据介绍，不压缩真实窗口补测。

## 异常与证据说明

前端参数 / 范围错误通常先被表单拒绝，不能说这些操作已产生 422。后端 bool、string、NaN / Infinity、重复创建 Result、并列和全空等规则用现有 pytest 展示；需要现场 API 验证时使用 Swagger，并保持总时长。Compare 的网络证据明确选用浏览器 Network 或后端访问日志，不声称二者都检查过。

如果服务不可用或遇到失败，展示真实错误与恢复，不剪成虚假的通过。窗口拖动无法完成就保持 AA 未勾选，不给出最终通过结论。关于 AI，只展示真实本聊天的阶段要求和对应 Git diff，不编造工具、Prompt 或人工审查经历。

## 演示后清理与交付

通过现有前端或正常 API 删除本轮剩余 EXP-002（及可选 EXP-003），再删其批次 / 项目；核对 A 的剩余资源，按照 Experiment → Batch → Project 顺序清理。Result 自动 CASCADE，不删数据库、不 SQL 强制清表。起始为空时应恢复四表各 0。

保存真实演示视频文件或课程允许的交付链接，检查完整播放、声音、操作过程及摄像头建议。录制成品尚不存在，6A 不填写伪造视频 URL。逐项完成 [最终验收清单](final-acceptance-checklist.md)，记录最终 SHA 后停止服务；评分由教师完成。
