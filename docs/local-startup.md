# Windows 一键启动与环境检查

适用于本地开发和课程演示，沿用 FastAPI + Vite 开发服务器。默认地址统一为 `http://127.0.0.1:5173/`，后端为 `127.0.0.1:8000`。启动器需要 Windows PowerShell 5.1（Windows 自带），不需要管理员权限。

## 日常使用

1. 双击项目根目录的 `启动平台.cmd`。
2. 等待环境检查、进程启动和服务就绪三个步骤。成功后自动打开首页；后端失败或前端代理不通不会显示启动成功。
3. 用完后双击 `停止平台.cmd`。关闭启动提示窗口或浏览器不会停止服务。

运行中的服务通过后台进程提供，重复启动会复用本工具管理且身份核验通过的服务。启动器不启用 Uvicorn 自动重载；日常录入无需重载，后端开发仍可按 README 使用手动开发命令。

命令行入口（从项目根目录运行）：

```powershell
# 不自动打开浏览器，适合终端验收
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\manage-local.ps1 -Action start -NoBrowser

# 停止本工具管理的服务
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\manage-local.ps1 -Action stop

# 主动进行详细诊断
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\manage-local.ps1 -Action diagnose
```

入口使用进程级 `ExecutionPolicy Bypass` 运行项目内脚本，不修改系统或用户的永久执行策略。组织强制策略仍可能阻止脚本，需要遵循该设备的管理要求。

## 第一次准备环境

启动器只检查已经准备好的环境，不自动安装或升级依赖，不联网查版本。将代码复制到新电脑时，应重新创建虚拟环境，不复制旧 `.venv`。

安装 Python 3.12 与符合 Vite 8 要求的 Node.js；当前要求 Node 20.19+（20.x）或 22.12+，项目已在 Node 24.15.0 验证。若使用 Windows Python Launcher，可从根目录执行：

```powershell
py -3.12 -m venv backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd --prefix frontend ci
```

没有 `py` 命令时，使用 Python 3.12 的完整路径创建环境。安装后重新打开终端，确保 `node.exe` 和 `npm.cmd` 在 PATH 中。无需激活 Conda 或虚拟环境，启动器直接调用 `backend/.venv/Scripts/python.exe`。

## 检查成本和运行边界

每次启动只做以下检查：

- 确认必要项目文件、虚拟环境 Python、Node/npm、前后端必要依赖可以使用；不导入业务应用进行预检查。
- 检查 8000 / 5173 的监听与进程归属。端口空闲时先通过 .NET 快速确认，无需加载端口进程查询模块。
- 启动后验证后端 `/health`、前端首页和经过 Vite 代理的 `/api/health`。现有 `/health` 会执行 `SELECT 1` 验证数据库连接；这不等同于完整数据库审计。

就绪检查默认最多等待约 60 秒，单个 HTTP 请求超时 2 秒，未通过的检查间隔约 0.5 秒，已就绪则提前结束。耗时包括本地进程查询与最后一个请求的收尾；可用 `-TimeoutSeconds 10` 缩短就绪等待，允许范围 1–60。此参数不控制依赖预检查或手动深入诊断耗时。

启动成功后管理脚本退出，停止检查，不设置定时任务、不新增页面轮询、不执行 pytest 或前端构建。网页现有的首页健康状态、比较自动同步等逻辑不受本工具改变。脚本显示当次环境检查和完整启动耗时，首次 Vite 编译及电脑性能会影响耗时。

## 进程与故障处理

- 固定端口，不自动改成 5174；仅监听 `127.0.0.1`。
- `.runtime/services.json` 保存项目路径、PID、创建时间、可执行文件和命令行。核验时同时检查实际进程身份和包含当前项目绝对路径的服务命令；不会只凭 PID 文件或端口结束进程。
- Python 虚拟环境可能存在启动器和实际服务两个进程，端口核验及停止会处理该启动器的子进程，并在停止前重新核验每个进程身份。
- 对于之前手动运行的服务，即使健康接口相同，也不自动接管。先回到原终端按 `Ctrl+C` 停止，再用一键入口启动。身份不明确的服务需人工核查。
- 本次启动部分失败时，只回收本次新启动的进程；启动前已由本工具管理的服务保留。若清理失败则保留记录供再次停止或诊断，不误报清理成功。
- 启动和停止共用文件锁，连续点击时提示已有操作进行中。持锁进程退出后操作系统释放锁，不用手动删除锁文件。
- 陈旧进程记录不会导致误停后来复用同一 PID 的其他程序；实际监听冲突仍会阻止启动。
- 项目移动后旧记录中的根路径不匹配，会拒绝使用。先在原路径停止服务；确认没有残留后再移走旧 `.runtime/services.json` 并重新启动。

启动正常执行既有后端初始化流程；启动工具不额外迁移、修复或清空数据库。实验数据仍位于 `backend/data/aiexphub.db`。

| 提示 | 处理方式 |
| --- | --- |
| 缺少后端虚拟环境 / Python 版本不符 | 按首次准备步骤使用 Python 3.12 创建虚拟环境 |
| 后端依赖不可用 | 使用虚拟环境解释器安装 `backend/requirements.txt` |
| Node/npm 不可用或版本不兼容 | 检查安装、版本和 PATH，重新打开终端 |
| 缺少前端依赖 | 在 `frontend` 执行 `npm ci` |
| 端口被其他进程占用 | 用 diagnose 查看 PID 和命令行，确认归属后手动停止 |
| 服务退出、超时或代理不通 | 查看下面的后端 / 前端日志和诊断结果 |
| 运行记录损坏 | 先 diagnose 核查实际进程，不直接删记录后强行重启 |

## 日志与深入诊断

日志保存在 `.runtime/logs/`，前后端的 stdout / stderr 分开记录。每次启动某服务时清理该服务旧日志，每类保留最多 5 份；复用服务不会新增日志。`.runtime/` 已被 Git 忽略。

`diagnose` 手动执行基础环境检查、`pip check`、`npm ls --depth=0`、端口与实际进程命令、两处健康检查，并展示最近的错误日志尾部。它不安装依赖、不调用业务写接口，也不启动或停止服务；输出面向本机排障，分享前自行检查日志内容。

## 验证记录（2026-10-24）

- 在 Windows PowerShell 5.1 执行脚本级自动测试：18 passed、0 failed，覆盖进程身份、PID 复用、父子进程端口归属、拒绝未知端口、失败清理、保留既有服务、重复启动、浏览器打开时机、代理就绪、超时、缺失环境及损坏记录等场景。命令见下文。
- 在真实项目执行启动、重复启动、停止和重新启动；重复启动前后进程记录一致。原手动服务被正确识别为端口冲突，未经工具自动结束。
- 在临时的“中文 + 空格”路径创建独立副本，实际启动和停止成功。仅复用已安装依赖，业务代码和数据库位于临时副本。
- 临时副本中模拟 Vite 配置报错，启动返回失败并清理本次进程，两端口无遗留监听；模拟虚拟环境和前端依赖缺失时给出具体提示。测试未删除或改动真实依赖。
- 实际持有管理锁时再次停止被拒绝，没有影响正在运行的服务。
- 原始项目表数据指纹和外键检查在验证前后对照，避免只凭记录数量判断数据保留。
- 优化端口空闲预检后，本机一次正常启动环境检查 1.75 秒、总计 5.26 秒；一次重复启动 7.94 秒（包含在用端口归属及健康核验）。这些是本机实测，不是对所有电脑的耗时承诺；检查完成后无常驻检查任务。

执行隔离的脚本测试（不启动真实服务、不访问业务数据库、无需 Pester）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\tests\run-tests.ps1
```

这套工具服务于本地运行与演示；正式部署的进程托管、HTTPS、远程访问和安装包另行规划。
