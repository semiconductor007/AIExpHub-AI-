# 比较页轻量自动同步

2026-10-24 经用户授权实现，仅增加前端通知与刷新行为，沿用现有只读 Compare API。未引入服务器推送、SSE、WebSocket、轮询、依赖或数据库变更。

## 使用方式

1. 在比较页加入至少两个实验，可选择基准，首次点击“开始比较”。只有用户开始过比较后才启用自动检查。
2. 同浏览器、同源的另一个页面保存已选实验结果后，比较页自动请求最新比较。实验编号 / 模型配置修改、相关项目的指标定义变化也会触发检查。
3. 切回已打开的比较页（窗口 focus 或页面重新可见）时检查一次最新数据，可补查外部 API 写入或漏收的通知。隐藏页面暂存刷新需求，重新可见后再请求。
4. “重新比较”仍可手动使用。改变基准、添加 / 移除 / 清空实验选择后会清除旧比较，等待用户重新开始；不擅自替用户开始新的比较。

实验选择、基准及当前滚动位置保留；综合图的图例显示开关也保留。首次图表初始化允许 ECharts 尚无 option，已有图表复用实例。表格、最佳 / 并列标签、差值、系统图和项目自定义图都使用同一次最新比较响应，不在前端重算指标。

## 通知与请求控制

- 优先使用 BroadcastChannel，同页通过本地事件处理；不支持时使用 storage 事件降级。通知只含版本、资源类型、资源 ID、删除标志及确保 storage 值变化的随机标识，不包含参数、指标数值或原结果 JSON。storage 降级仅覆盖一个固定通知键，不保存比较集合或结果历史。
- 同源包括协议、主机和端口一致，例如统一使用 `http://127.0.0.1:5173`；`localhost` 与 `127.0.0.1` 不属于同源。不同浏览器 / 设备不保证立即通知，回到页面时仍可重新查询。
- 仅在写入请求成功后通知；失败写入不通知。通知 API 不可用或存储受限时，不把成功保存误报为失败，仍保留切回页面及手动刷新。
- 按已选 Experiment ID / 所属 Project ID 筛选相关变化，未参与比较的实验更新不请求比较。新实验创建和批量新增不触发无关刷新。
- 连续通知及配对的 focus / visibilitychange 在 250 ms 内合并。比较请求进行中又收到变化时，只保留一次后续检查，当前请求结束后补查，避免漏掉刚保存的数据。
- 手动刷新吸收已排队的检查；选择变化、资源失效或离开页面时清理队列。请求版本号和 AbortController 防止旧请求覆盖新状态；退出路由时移除事件监听和关闭通道。
- 无定时轮询，也不在失败后无限重试；新通知、切回页面或手动操作可以重新发起检查。

## 状态与异常

页面显示“正在自动获取最新比较结果”或最近获取时间。收到变更但尚未核实最新数据时，标明下方是上次成功获取的结果。

- 网络 / 服务失败：保留已有表格和图表，明确显示“更新失败，当前显示上次成功数据”，可手动重试。自动失败使用页面提示，不连续弹出 toast。
- 收到已选实验删除通知：立即作废旧结果、取消旧请求，保留选择并提示移除失效实验。查询时发现实验不存在（404）也清除旧表图，停止自动检查，待用户修正选择后重新比较。
- 保留数据只适用于刷新失败；不会把已知删除的实验继续展示为有效结果。
