# AI 实验总结实施方案

更新日期：2026-10-27。状态：A / B / C 已实现，D 已完成自动化与模拟页面验证；真实模型调用待本地配置后验收。实际配置、协议与验证见 [AI 总结使用说明](ai-experiment-summary.md)。下述内容保留审核方案与范围。

## 目标与第一版范围

在已有实验比较页增加“AI 实验总结”，帮助用户解释当前实验的指标表现、参数变化及后续验证方向。后端负责真实数据和数值计算，DeepSeek 负责解释，ECharts 继续负责绘图。

- 第一版限同一个 Project 的 2–10 个不同实验，允许不同 Batch、模型名称；这只是范围限制，不代表评测条件一定一致。现有跨项目比较和导出不受影响。
- 所有实验必须存在；至少两个实验有 Result，且至少一项指标在两个实验中都有非 null 值，否则说明原因，不调用模型。
- 无结果的实验可以列入缺失清单；单项缺失保持 null，不能补 0。最佳 / 并列最佳、方向、单位、基准差值复用现有后端规则。
- 可选一个主评价指标。选中时，该指标须至少有两个有效实验；未选时按指标分别总结，不生成综合评分或总冠军。
- 可选基准，必须属于本次实验；基准缺失某指标时，该指标差值不可用，不推测补齐。
- 只手动生成、重新生成和复制文本；不做自由聊天、总结历史表、自动训练、联网检索、AI 自动修改数据或完整报告排版。

## 页面使用流程

1. 用户在比较页选好实验，正常查看表格和图表，再点击“AI 实验总结”。
2. 弹窗选择主指标（可不选），核对基准，并按参数路径勾选允许发送的参数；参数默认不勾选。参数叶子路径支持嵌套对象 / 数组，缺失与显式 null 区分，字段名包含点号时不能发生路径混淆。
3. 后端准备快照。页面展示将发送的实验编号、模型、指标、已选参数，以及数据缺失和评测条件提示；可展开查看完整发送数据。用户确认范围后点击“发送并生成”。
4. 展示生成进度，禁止重复点击；原表格和图表仍可查看。成功后展示固定章节、数据获取时间、生成时间、实际模型和“AI 建议，需人工核对”。
5. 配置 / 结果 / 指标定义、选择、基准、主指标或参数范围变化时，原总结标明已过期；不自动付费重新生成。页面离开后不持久化总结，复制过期内容也须携带过期标记。

参数未发送时只总结指标，不假装知道训练配置。评测集、版本、split、评测方法可沿用 parameters.evaluation 的可选填写约定，不改动现有参数必填规则，不将未提供的条件视为一致。

## 数据快照与发送范围

现有 compare 响应没有 parameters，因此后续在独立的总结服务中读取 Experiment、Batch 所属项目、当前 Result 与项目指标定义；不能仅将前端比较表打包发给模型。尽量复用纯比较计算，避免改变原比较接口契约。

| 数据 | 处理 |
| --- | --- |
| 实验编号、模型名称、内部关联标识 | 预览后发送，用于准确引用；编号和名称也可能包含敏感信息，预览明确展示 |
| 指标定义、实际值、缺失状态 | 发送；保留项目作用域、键、单位和方向，不发送伪造或补齐值 |
| 最佳 / 并列、基准差值 | 后端确定性计算后发送，并分配证据标识 |
| parameters | 只读取用户勾选的路径和值；不自动发送整个对象 |
| 备注、项目 / 批次 description、原始 JSON 文件、日志、附件 | 默认排除，第一版不提供额外上传入口 |
| API Key、系统环境变量 | 永远不进入提示词、前端响应、复制内容或日志 |

请求只接受实验 ID、基准 ID、主指标标识和参数路径等选择项。所有数值及关联以数据库为准。自定义指标以项目作用域与指标 ID / key 定位，不以显示名称合并。

预览和调用之间也可能发生修改：预览返回规范化快照摘要，生成时重新读取并核对摘要；不一致则要求重新预览，不能悄悄发送用户未确认的新数据。摘要覆盖选择、编号、模型、勾选参数、指标定义 / 数值和计算规则版本，不只依赖 Result.updated_at。快照在短只读事务内固定，调用外部模型前释放数据库事务。

模型调用结束后再次检查数据是否变化；若已变化，输出只能标明属于旧快照，不能冒充当前总结。前端继续复用同源变更通知和切回页面核对机制，并用请求序号避免旧响应覆盖新选择。无需服务器推送，也不承诺对外部直接改库实时感知。

## 总结内容与可验证性

固定五个章节：

1. **实验概况**：参与实验、模型、有效 / 缺失结果数量、主指标与基准。
2. **指标表现**：逐项最佳 / 并列、基准收益与代价，明确数据缺失。
3. **参数差异解释**：仅依据已发送参数描述伴随变化；区分观察与待验证推测。
4. **局限与权衡**：指标之间的取舍、评测条件不明、样本不足、多参数同时变化。
5. **下一步建议**：建议控制变量、补录缺失指标或重复实验，不自动创建实验。

数值事实由后端生成的事实表展示；模型输出结构化 JSON，包含章节、叙述、引用的实验 / 指标 / 证据标识，不由模型重新生成表格、图表数值或最佳排名。返回结构须校验字段类型、长度、允许的章节、ID 归属及证据引用，未知引用和结构错误拒绝显示为有效总结。

JSON 格式正确和引用存在并不等于推理正确。第一版不承诺自动证明每一句自然语言；模型叙述需保留“观察 / 推测 / 建议”区别，与真实事实卡片一起供用户核对。

- 同项目不自动等于同数据集、同测试划分、同硬件或同指标口径；信息不足时明确指出，不能做公平性保证。
- 多个参数同时变化时不把提升归因于单一参数；单次实验不声称统计显著、稳定提升或泛化能力已验证。
- accuracy 从 0.80 到 0.86 是绝对增加 0.06（6 个百分点），不是相对增加 6%；第一版沿用绝对差值。
- 缺失、全空、并列、指标方向和不同单位遵守现有比较规则；不跨单位做加权总分。
- 实验名称、参数字符串均视为数据，不能覆盖系统规则。模型不能调用数据库写操作、执行代码或访问工具；前端按纯文本 / 安全组件渲染，不执行生成 HTML、脚本或外部图片链接。

## 图表方案

第一版使用当前 ECharts 图表、真实比较数据和已有 PNG 导出，不新增模型画图接口，也不要求 DeepSeek 返回图片。

AI 总结与图表属于同一组实验，但数据刷新后旧总结可能过期：界面必须醒目标明，不能把旧总结与新图表包装成同一份新报告。第一版复制总结带快照时间和状态，不新增“整份报告”导出。

以后若需要 AI 推荐图形，只允许返回受控图表类型与指标 ID，由应用校验并从真实快照取值；这是后续范围。训练曲线需要真实 epoch / step 历史数据，不能把创建时间当训练过程或编造趋势。

## API 配置位置（已实现后端读取）

- 本地填写文件：`backend/.env`。本轮创建空配置；已有文件则保留，不覆盖。
- 可提交模板：`backend/.env.example`。模板永远没有真实密钥。
- 现有 `.gitignore` 已忽略 `.env`，并允许 `.env.example`；不要强制提交本地密钥。
- 本地配置读取已实现；填写 Key / 模型并改为 `AI_SUMMARY_ENABLED=true`，重启后端即可启用。启动和健康检查不调用模型。

| 配置 | 用途 / 初始值 |
| --- | --- |
| `AI_SUMMARY_ENABLED` | 默认 `false`；关闭时核心平台仍可用 |
| `DEEPSEEK_API_KEY` | 留空，由用户在本地填入实际 Key |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com`，是服务根地址，不包含 `/chat/completions` |
| `DEEPSEEK_MODEL` | 留空，接入时填写账户可用模型 ID，不能填写聊天页面地址或模型昵称 |
| `AI_SUMMARY_TIMEOUT_SECONDS` | 初始 60 秒总调用超时 |
| `AI_SUMMARY_MAX_OUTPUT_TOKENS` | 初始 3000，适配实际模型后核验 |
| `AI_SUMMARY_MAX_EXPERIMENTS` | 初始 10 |
| `AI_SUMMARY_MAX_INPUT_BYTES` | 初始 32768，限制完整序列化消息的 UTF-8 字节数；不是 token 或费用估算 |

配置加载固定定位 backend/.env，不受工作目录影响；进程环境变量优先于文件，首次使用后缓存，修改须重启。配置不进入 VITE_*，前端只获取启用 / 可配置状态，不能读取 Key。真实 Key 不要发到聊天中。

第一版仅接官方 DeepSeek HTTPS 服务；地址仅由后端本地配置，不接受浏览器提交地址，不自动跟随可能携带鉴权的跨站重定向。错误和日志只留状态、耗时、请求标识等必要诊断，不记录 Authorization 或完整提示词 / 返回正文。

## 调用控制与异常行为

- 第一版使用一次非流式请求；按生成按钮才请求，不在页面刷新、比较自动同步、平台启动或健康检查时调用模型。
- 超过输入限制先提示缩小参数 / 实验范围，不静默截断关键数据。输出 JSON 为空、截断、结构不符或引用错误时提示生成失败，不展示半份可信总结。
- 不自动重试付费调用。用户可手动重试，并提示前一次超时不一定代表服务商没有处理或计费。费用由真实模型、输入 / 输出 token 和服务商价格决定，不预先承诺固定金额。
- 前端禁止重复点击，后端以单进程并发上限 1 及短期请求标识防止重复发送；这是当前本地单进程部署的边界，不伪装成多进程全局防重。
- 缺少 Key / 模型、功能关闭、鉴权失败、额度不足、限流、网络失败、超时等分别有可理解提示；不会使原 CRUD、比较、图表或导出失败。
- 页面取消 / 离开后丢弃迟到响应，尽力取消网络请求；不能保证服务商停止处理或撤销费用。
- 无总结历史表、不修改现有业务数据。模型不可用时原比较事实继续可见，但不能把本地事实摘要冒充 AI 成功结果。

## 实施顺序和验收

| 阶段 | 产物 | 验收 |
| --- | --- | --- |
| A：快照与协议 | 独立总结服务、参数路径选择、预览摘要、确定性事实和返回 Schema | 同项目 / 数量、资源缺失、缺失指标、0、并列、自定义方向、基准、输入大小；预览后变更阻止发送 |
| B：DeepSeek 接入 | 后端配置加载、客户端、超时 / 防重、响应校验 | 使用模拟响应验证空 / 错误 JSON、截断、未知引用、401 / 429 / 超时；日志和响应不泄露 Key，测试不调用付费模型 |
| C：比较页交互 | 数据范围预览、生成 / 复制、错误与过期状态 | 参数默认不外发，重复点击不重复请求；生成期间数据变化、换选择、切页面、自动刷新均不展示伪“最新”总结 |
| D：真实验收 | 少量真实调用、使用说明、回归记录、独立提交 | 用户填好 Key 后，以独立测试数据核对事实和中文说明；运行后端 / 前端测试与构建，原数据、现有导出和比较保留 |

正式实施时再确定端点及具体协议字段，先完成 A / B 模拟验收再进入真实调用。不需数据库迁移；仅添加必要依赖，不搭建复杂 Agent / RAG 架构。

已冻结：同项目 2–10 个实验、主指标可选、参数明确勾选、无历史、手动生成、复用图表。待实际接入时填写：Key 与账户可用模型 ID。没有其他阻碍基础设计的未决业务问题；评测条件不完整通过局限提示处理，不能由 AI 补造。
